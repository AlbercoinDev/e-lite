# F2 — Arranque autónomo, gestión de Core y poda local

**Fecha:** 2026-11-02 · **Base:** `v0.1.0-alpha.10` + cambios de esta iteración
**Objetivo:** verificar el arranque desde cero, el lanzamiento de Core, la espera
de Core y el IBD con poda local sin huecos.

## Entorno de laboratorio

- Linux x86_64, Bitcoin Core `v32.1.0`.
- Regtest con `-fastprune` para forzar ciclos de poda rápidos.
- e-lite en modo `debug` (`cargo build -p e-lite`).

## Observaciones de rendimiento (regtest)

- Ingesta bulk con bloques de 1 tx: >10.000 bloques/s en el arranque.
- La poda manual se ejecuta cuando la altura segura avanza; en la prueba,
  `pruneheight=1785` con índice en 2101, dejando 288 bloques de margen + undo.
- La guarda de lag no pausa mientras `pruneheight == 0` (Core aún no ha podado).
  Después usa la retención real (`blocks - pruneheight`) con 512 bloques de
  margen y reanuda al 75%.

## Signet / testnet4: intento de sincronización completa

La forma más simple es el all-in-one, que instala/actualiza, configura, ejecuta y
escribe el informe:

```bash
bash scripts/e-lite-all-in-one.sh --network signet --acceptance --with-core --yes
bash scripts/e-lite-all-in-one.sh --network testnet4 --acceptance --with-core --yes
```

El harness subyacente está en `tests/e2e_networks.sh`:

```bash
E_LITE_NETWORK=signet E_LITE_E2E_REQUIRED_FREE_GIB=15 tests/e2e_networks.sh
E_LITE_NETWORK=testnet4 E_LITE_CORE_DATADIR=/srv/core-t4 \
  E_LITE_E2E_REQUIRED_FREE_GIB=20 tests/e2e_networks.sh
```

Hace un IBD real con Core lanzado por e-lite (`prune=550`), espera `READY` en el
tip, comprueba `indexed_height >= pruneheight`, consulta Electrum y mide el
tiempo total.

### Resultado de los dos intentos en este host (2026-11-02)

| Intento | Disposición | Resultado |
|---|---|---|
| 1 | Core datadir en `/tmp` (tmpfs 3,9 GB), índice en disco | ❌ `/tmp` se llenó (60 MB libres); índice en 227.626, `pruneheight` 255.988. Parado. |
| 2 | Core datadir e índice en disco (`/`, 11 GB libres) | ❌ `/` se llenó (49 MB libres); índice en 253.413, `pruneheight` 263.941; Core entró en bucle de reinicio por falta de espacio. Parado. |

**Causa raíz del intento 2:** `supervisor_tick` llamaba primero a
`core.blockchain_info()?`; cuando Core estaba cargando el índice o el RPC
fallaba, el guard de disco nunca se evaluaba. El indexador tampoco tenía un
chequeo de disco independiente. Con `min_free_gib = 2` y ~9,4 GB de datos
(Core + índice) en un disco de 11 GB libres, el disco llegó a 49 MB antes de
que el guard actuara. El hueco resultante (`indexed < pruneheight`) es
irrecuperable sin snapshot o nodo completo.

**Correcciones implementadas:**
- `Supervisor::disk_tick` evalúa el disco **sin depender del RPC de Core**.
- `supervisor_tick` lee el espacio libre **antes** de `blockchain_info`.
- `Indexer::disk_guard` comprueba ambos filesystems antes del RPC y cada segundo
  durante la aplicación de bloques.
- Si el disco está bajo, el indexador no confirma el grupo en curso: se descarta
  y se reindexa cuando haya espacio.
- Al hacer reorg se relee el tip comprometido después del rewind.
- Aviso al arrancar si el espacio libre está por debajo de `min_free_gib`.
- `tests/e2e_networks.sh` acepta `E_LITE_E2E_REQUIRED_FREE_GIB` y muestra el
  espacio libre antes de empezar.
- Histeresis adaptativa: `resume = low + (low/2).clamp(512 MiB, 5 GiB)`. Con
  `min_free_gib=2` reanuda a 3 GB, no a 7 GB; así un disco pequeño no queda
  bloqueado para siempre.

### Espacio en este host

```
/ (41 GB)  29 GB usados  11 GB libres
/home/albit/e-lite-signet-core-disk  3,5 GB   (eliminado tras el fallo)
/home/albit/e-lite-signet-index-disk 5,9 GB   (eliminado tras el fallo)
target 1,6 GB · .cache 4,9 GB · .rustup 1,3 GB
```

El intento 2 escribió ~9,4 GB (Core + índice) y dejó el disco en 49 MB. Para
signet completo hacen falta **≥15 GB libres**; para testnet4, **≥20 GB**. Este
host no cumple el requisito; el preflight rechaza la ejecución por defecto. Es
un bloqueo de infraestructura: hay que liberar espacio o usar otro disco/host.

**Pendiente:** repetir signet/testnet4 en un host con **≥15/20 GB libres**,
idealmente con Core e índice en discos separados. Los resultados reales deben
añadirse a esta tabla; no se declara la aceptación completa hasta entonces.

## Criterio de aceptación

- Arrancar e-lite sin Core: queda `WAITING_FOR_CORE`.
- Core aparece y e-lite auto-inicializa sin reiniciar.
- Core lanzado por e-lite se detiene al salir e-lite (si `stop_on_exit=true`).
- Core externo pruned + índice vacío falla limpio y no se pausa.
- IBD pruned local no pierde bloques y termina `READY`.
